🧬 Fragment Classification

Purpose: Classify fragmented or incomplete transposable elements using sequence-based approaches.

What are Fragments?

Fragments are broken or incomplete pieces of transposable elements that may result from:

  • Genomic degradation or truncation
  • Partial element insertions
  • Sequencing or assembly artifacts

Input Dataset Example

>TE_fragment_1
ATCGATCGATCGATCGATCGATCG...
>Partial_Copia_LTR
TGTTGCATGTCGATCGTAGC...
>Truncated_Gypsy_internal
GCTAGCTAGCTAGCTAGCTA...

Note: Sequences can be any length, from small fragments (~100 bp) to partial elements (several kb).

Available Models

  • ClassifyTE — Hierarchical stacking machine learning using k-mer features

    📦 ClassifyTE_combined (26 classes):

    • Class I Retrotransposons: LTR (Copia, Gypsy, Bel-Pao), DIRS, LINE (R2, RTE, Jockey, L1, I), SINE (tRNA, 7SL, 5S)
    • Class II DNA transposons: TIRs (Tc1-Mariner, hAT, Mutator, Merlin, Transib, P, PiggyBac, PIF-Harbinger, CACTA)

    📦 ClassifyTE_pgsb (9 classes - plant-focused):

    • Focus: Plant-specific TE families from PGSB database
    • Classes: LTR (Copia, Gypsy), LINE, SINE, Mutator, PIF-Harbinger, CACTA

    📦 ClassifyTE_repbase (24 classes - comprehensive):

    • Source: RepBase curated database
    • Coverage: Complete hierarchical classification from Class I/II down to specific superfamilies
  • TERL — Convolutional neural network for deep learning classification

    🧬 DS1 (7 superfamilies - RepBase):

    • Copia, Gypsy, Bel-Pao, ERV, L1, Tc1-Mariner, hAT

    🧬 DS2 (3 orders - RepBase):

    • Class II, LTR, LINE

    🧬 DS3 (11 superfamilies - 7 databases):

    • Copia, Gypsy, Bel-Pao, ERV, L1, SINE, Tc1-Mariner, hAT, Mutator, PIF-Harbinger, CACTA

    🧬 DS4 (4 orders - 7 databases):

    • Class II, LTR, LINE, SINE

    🧬 DS5 (3 orders - cross-database validation):

    • Class II, LTR, LINE (trained on RepBase, tested on other databases)

🔬 Protein Domain Detection

                        
Purpose: Identify conserved functional domains within transposable element proteins.


                        

                            
What are Domains?

                            
Domains are evolutionarily conserved functional modules in proteins, such as:

                            
    
                                
  • RT (Reverse Transcriptase) - copies RNA to DNA
    • 
                                
  • RNase H - degrades RNA in RNA-DNA hybrids
    • 
                                
  • Integrase - integrates DNA into genome
    • 
                                
  • GAG - structural protein
    • 
                                
  • Protease - processes polyproteins
    • 
                            


                            
Input Dataset Example

                            
>RT_domain_sequence_1
ATGGCTAGCTAGCTAGCATGCTAGCTAGC...
>Integrase_region_2
GCTAGCTAGCTAGCTAGCTAGCTAGCTAG...
>GAG_protein_coding
TGATCGATCGATCGATCGATCGATCGATC...

                            
Note: Sequences should contain protein-coding regions. YORO analyzes windows to detect domain presence.


                            
Available Models & Detectable Domains

                            
    
                                
  • YORO — Deep neural network (YOLO-inspired) for LTR-retrotransposon domain detection. Detects:

      • 
                                        
    • ENV (Envelope protein)
      • 
                                        
    • INT (Integrase)
      • 
                                        
    • AP (Aspartic Protease)
      • 
                                        
    • RNASEH (RNase H)
      • 
                                    
    
                                
    •

🧬 Complete LTR-Retrotransposon Detection

                        
Purpose: Identify and classify structurally intact LTR-retrotransposons with complete LTR-internal-LTR architecture.


                        

                            
What are Complete Elements?

                            
Complete LTR-retrotransposons have the canonical structure:

                            
[TSD] [LTR-5'] --[PBS]--[GAG-POL]--[PPT]-- [LTR-3'] [TSD]
 5bp   300-600bp        4-10 kb           300-600bp  5bp


                            
Input Dataset Example

                            
>Complete_Copia_element_Chr1:12345-20000
TGTTGCATGTCG...ATCGATCG...TGTTGCATGTCG
>Intact_Gypsy_LTR_RT_scaffold_5
AGATCTCGATCG...GCTAGCTA...AGATCTCGATCG
>Full_LTR_retrotransposon_contig_23
GCTAGCTAGCTA...ATCGATCG...GCTAGCTAGCTA

                            
Requirements:

                            
    
                                
  • Elements must have both LTRs (left and right)
    • 
                                
  • Typical size: 4-15 kb
    • 
                                
  • Best for genome assemblies, long contigs, or curated element collections
    • 
                            


                            
Available Models & Classifications

                            
    
                                
  • Inpactor2 — Structure-based LTR_FINDER + Deep Neural Networks for complete LTR-retrotransposon detection and classification
                                    
      
                                        
    • Superfamily: Copia (RLC) and Gypsy (RLG)
      • 
                                        
    • Lineages/Families:
      • 
                                    
    
                                    
    
                                        
    Copia lineages: ALE, ALESIA, RETROFIT, ANGELA, BIANCA, IKEROS, IVANA, ORYCO, OSSER, TAR, TORK, SIRE
    
                                        
    Gypsy lineages: CRM, GALADRIEL, REINA, TEKAY, DEL, ATHILA, TAT
    
                                    
    
                                
    • 
                                
  • YORO — Deep Learning for LTR-retrotransposon protein domain detection and classification
                                    
      
                                        
    • Detection type: Protein domains in LTR-retrotransposons
      • 
                                        
    • Domain classes (6):
      • 
                                    
    
                                    
    
                                        
    Domains: GAG (structural protein), POL (polyprotein), ENV (envelope protein), RT (reverse transcriptase), INT (integrase), AP (aspartic protease), RNASEH (RNase H)
    
                                    
    
                                
    • 
                            


                            
Server behavior

                            
    
                                
  • The API queues jobs and returns immediately with a job id and output path.
    • 
                                
  • Inpactor2 uses ltr_finder for structural detection followed by neural network classification.
    •

Map Labels

                
Purpose: Map FASTA headers into hierarchical codes or add actual
                    labels to an existing predictions CSV. This operation is asynchronous and will queue a job for
                    processing. When validateOnly=true, the server will only validate mappings and will not write
                    output.


                

                    
Inputs

                    
    
                        
  • FASTA (file) — required. FASTA should use the standard header format
                            expected by the mapper.
    • 
                        
  • predictionsFile (CSV) — optional. If provided the mapper will attempt to
                            add Actual_Label/Actual_Code columns into the predictions CSV.
    • 
                        
  • validateOnly — when set to true, the server will only validate mappings and
                            will not write a mapped output file.
    • 
                    


                    
Server behavior

                    
    
                        
  • The API will use the default server-side tree file and will auto-generate an output path
                            when needed.
    • 
                        
  • If validateOnly=true the server returns diagnostics and does not produce a
                            result file.
    • 
                    

                

                    

                        
                    

                    

                    

                    

                        Note: If validateOnly=true the server performs only validation and
                        will not write a mapped output file.
                    


                    
                    

                

            


            

                
Evaluate — Generate Metrics

                
Purpose: Compute standardized evaluation metrics from a predictions
                    CSV (must contain ground-truth labels when required). The job runs asynchronously and returns a job
                    id immediately.


                

                    
Inputs

                    
    
                        
  • predictionsFile (CSV) — required. The CSV should contain at minimum the
                            columns used by the evaluator (e.g. Actual_Label,
                            Predicted label).
                        
    • 
                        
  • format — choose detailed, summary or
                            json depending on the output you need.
                        
    • 
                    


                    
Server behavior

                    
    
                        
  • The server sets verbose=true and will create an output directory automatically
                            when omitted.
    • 
                        
  • The evaluator generates JSON and text reports; include Actual_Label in the predictions CSV
                            to produce full metrics.
    • 
                    

                


                    

                        
                    

                    

                    
The server enforces verbose=true for /evaluate.

⚠️ Important Information

                

                    
🔄 Asynchronous Processing

                    
All classification and evaluation jobs are processed asynchronously. The API returns immediately with a job ID - you don't need to wait for processing to complete. Check your email for results.

                


                

                    
📧 Email Notifications

                    
Results are automatically sent to your notification email when jobs complete. Includes result links and file attachments. Important: Output files are removed from the server after email delivery for security and storage optimization.

                


                

                    
📁 Auto-Generated Outputs

                    
Output directories are created automatically with timestamps if not specified. The server handles all file organization - you only need to provide input files.

                


                

                    
⚙️ Server Defaults

                    
The following parameters are automatically enforced for optimal results:

                    
    
                        
  • clean=true — Removes temporary files after processing
    • 
                        
  • verbose=true — Provides detailed logging output
    • 
                        
  • autoLabel=true — Automatically labels sequences for classification
    • 
                    

                


                

                    
💡 Pro Tip

                    
For best results: Fragments for broken sequences, Domains for protein analysis, Complete Elements for intact LTR-RTs. Use Map Labels before evaluation to ensure proper taxonomy mapping.
