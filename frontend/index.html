Run — Classification

Purpose: Start an asynchronous classification job. Upload a FASTA file and choose a model to run; the server will queue the job and return immediately with a job id and output path. Some parameters are enforced by the server.

Inputs

  • FASTA (file) — required. FASTA file with sequence headers expected by the selected model.
  • model — choose one of classifyte, terl, or yoro.
  • modelFile — optional selection of the model to use (lists available models for the selected model type).
  • ClassifyTE-specific options: algorithm (LCPNB or NLLCPN) and
  • YORO-specific options: window, threads, threshold, cycles, and autoLabel.

Server behavior

  • The API queues jobs and returns immediately with a job id and output path.
  • The server will auto-generate the output directory when you omit it.
  • Server-enforced flags: clean=true, verbose=true, and autoLabel=true for /run. You can still pass these fields but the server may override them.
Available ClassifyTE models:
  • ClassifyTE_combined
  • ClassifyTE_pgsb
  • ClassifyTE_repbase

    🧬 Fragment Classification

    Purpose: Classify fragmented or incomplete transposable elements using sequence-based approaches.

    What are Fragments?

    Fragments are broken or incomplete pieces of transposable elements that may result from:

    • Genomic degradation or truncation
    • Partial element insertions
    • Sequencing or assembly artifacts

    Input Dataset Example

    >TE_fragment_1
ATCGATCGATCGATCGATCGATCG...
>Partial_Copia_LTR
TGTTGCATGTCGATCGTAGC...
>Truncated_Gypsy_internal
GCTAGCTAGCTAGCTAGCTA...

    Note: Sequences can be any length, from small fragments (~100 bp) to partial elements (several kb).

    Available Models

    • ClassifyTE — Hierarchical stacking machine learning using k-mer features
      • Retrotransposons: LTR (Copia, Gypsy, Bel-Pao), DIRS, LINE (R2, RTE, Jockey, L1, I), SINE (tRNA, 7SL, 5S)
      • DNA transposons: TIRs (Tc1-Mariner, hAT, Mutator, Merlin, Transib, P, PiggyBac, PIF-Harbinger, CACTA)
    • TERL — Convolutional neural network for deep learning classification
      • DS1: Superfamilies (Copia, Gypsy, Bel-Pao, ERV, L1, Tc1-Mariner, hAT)
      • DS2: Orders (Class II, LTR, LINE)
      • DS3: Extended superfamilies (Copia, Gypsy, Bel-Pao, ERV, L1, SINE, Tc1-Mariner, hAT, Mutator, PIF-Harbinger, CACTA)
      • DS4: Extended orders (Class II, LTR, LINE, SINE)
      • DS5: RepBase-trained (Class II, LTR, LINE)

    Server behavior

    • The API queues jobs and returns immediately with a job id and output path.
    • The server will auto-generate the output directory when you omit it.
    • Server-enforced flags: clean=true, verbose=true, and autoLabel=true for classification.
    Available ClassifyTE models:
    • ClassifyTE_combined
    • ClassifyTE_pgsb
    • ClassifyTE_repbase
    Available TERL model folders:
    • DS1
    • DS3
    Note: The server enforces defaults for several parameters (for example, clean=true, verbose=true and autoLabel=true). 
    
                        
                    
    

                    
                    
    
                        
    🔬 Protein Domain Detection
    
                        
    Purpose: Identify conserved functional domains within transposable element proteins.
    

                        
    
                            
    What are Domains?
    
                            
    Domains are evolutionarily conserved functional modules in proteins, such as:
    
                            
      
                                
    • RT (Reverse Transcriptase) - copies RNA to DNA
      • 
                                
    • RNase H - degrades RNA in RNA-DNA hybrids
      • 
                                
    • Integrase - integrates DNA into genome
      • 
                                
    • GAG - structural protein
      • 
                                
    • Protease - processes polyproteins
      • 
                            
    

                            
    Input Dataset Example
    
                            
    >RT_domain_sequence_1
ATGGCTAGCTAGCTAGCATGCTAGCTAGC...
>Integrase_region_2
GCTAGCTAGCTAGCTAGCTAGCTAGCTAG...
>GAG_protein_coding
TGATCGATCGATCGATCGATCGATCGATC...
    
                            
    Note: Sequences should contain protein-coding regions. YORO analyzes windows to detect domain presence.
    

                            
    Available Models & Detectable Domains
    
                            
      
                                
    • YORO — Deep neural network (YOLO-inspired) for LTR-retrotransposon domain detection. Detects:
                                    
        
                                        
      • RT (Reverse Transcriptase)
        • 
                                        
      • GAG (Structural protein)
        • 
                                        
      • ENV (Envelope protein)
        • 
                                        
      • INT (Integrase)
        • 
                                        
      • AP (Aspartic Protease)
        • 
                                        
      • RNASEH (RNase H)
        • 
                                    
      
                                
      • 
                            
    

                            
    Server behavior
    
                            
      
                                
    • The API queues jobs and returns immediately with a job id and output path.
      • 
                                
    • Server-enforced flags: clean=true, verbose=true, and autoLabel=true.

    🧬 Complete LTR-Retrotransposon Detection
    
                        
    Purpose: Identify and classify structurally intact LTR-retrotransposons with complete LTR-internal-LTR architecture.
    

                        
    
                            
    What are Complete Elements?
    
                            
    Complete LTR-retrotransposons have the canonical structure:
    
                            
    [TSD] [LTR-5'] --[PBS]--[GAG-POL]--[PPT]-- [LTR-3'] [TSD]
 5bp   300-600bp        4-10 kb           300-600bp  5bp
    

                            
    Input Dataset Example
    
                            
    >Complete_Copia_element_Chr1:12345-20000
TGTTGCATGTCG...ATCGATCG...TGTTGCATGTCG
>Intact_Gypsy_LTR_RT_scaffold_5
AGATCTCGATCG...GCTAGCTA...AGATCTCGATCG
>Full_LTR_retrotransposon_contig_23
GCTAGCTAGCTA...ATCGATCG...GCTAGCTAGCTA
    
                            
    Requirements:
    
                            
      
                                
    • Elements must have both LTRs (left and right)
      • 
                                
    • Typical size: 4-15 kb
      • 
                                
    • Best for genome assemblies, long contigs, or curated element collections
      • 
                            
    

                            
    Available Models & Classifications
    
                            
      
                                
    • Inpactor2 — Structure-based LTR_FINDER + Deep Neural Networks for complete LTR-retrotransposon detection and classification
                                    
        
                                        
      • Superfamily: Copia (RLC) and Gypsy (RLG)
        • 
                                        
      • Lineages/Families:
        • 
                                    
      
                                    
      
                                        
      Copia lineages: ALE, ALESIA, RETROFIT, ANGELA, BIANCA, IKEROS, IVANA, ORYCO, OSSER, TAR, TORK, SIRE
      
                                        
      Gypsy lineages: CRM, GALADRIEL, REINA, TEKAY, DEL, ATHILA, TAT
      
                                    
      
                                
      • 
                                
    • YORO — Deep Learning for LTR-retrotransposon protein domain detection and classification
                                    
        
                                        
      • Detection type: Protein domains in LTR-retrotransposons
        • 
                                        
      • Domain classes (6):
        • 
                                    
      
                                    
      
                                        
      Domains: GAG (structural protein), POL (polyprotein), ENV (envelope protein), RT (reverse transcriptase), INT (integrase), AP (aspartic protease), RNASEH (RNase H)
      
                                    
      
                                
      • 
                            
    

                            
    Server behavior
    
                            
      
                                
    • The API queues jobs and returns immediately with a job id and output path.
      • 
                                
    • Inpactor2 uses ltr_finder for structural detection followed by neural network classification.
      •

    Quick reference — endpoints
    

            
    
                
    /run — classification
    
                
    Purpose: Classify transposable elements in DNA sequences using machine learning models. Upload a FASTA file containing DNA sequences and select a classification model (ClassifyTE, TERL, or YORO). The system automatically labels sequences, runs the selected model, and optionally evaluates the results against known annotations.
    
            
    

            
    
                
    /map-labels — FASTA header mapping
    
                
    Purpose: Standardize and validate FASTA sequence headers according to a hierarchical taxonomy. This command maps custom or inconsistent sequence labels to a unified classification tree, ensuring compatibility across different tools and datasets. Useful for preparing datasets or validating existing annotations.
    
            
    

            
    
                
    /evaluate — metrics
    
                
    Purpose: Assess classification model performance by computing comprehensive metrics (precision, recall, F1-score, confusion matrices). Compare predicted labels against ground-truth annotations to quantify model accuracy at multiple taxonomic levels. Produces both human-readable reports and machine-readable JSON output.
